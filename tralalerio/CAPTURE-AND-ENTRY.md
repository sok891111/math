# 포획·등장·교대 연출

원본 확인 기준은 로컬 `pokemon-gold-kr-research`의 커밋 `c90f31dadef17f033a8f1bdada701b26cef18241`이다.

- `data/moves/animations.asm`: `BattleAnim_ThrowPokeBall`, `BattleAnim_SendOutMon.Normal`, `BattleAnim_ReturnMon`
- `engine/battle_anims/functions.asm`: 포물선 투척, 네 번의 바운스, 볼 프레임 상태 전환
- `engine/battle_anims/pokeball_wobble.asm`, `data/battle/wobble_probabilities.asm`: 선행 성공 판정과 별도 흔들림 판정
- `data/battle_anims/framesets.asm`, `oam.asm`: 볼·연기 그래픽 배치, 반전, 프레임 대기
- `engine/battle_anims/bg_effects.asm`: 회수/등장 시 몬스터 크기 단계
- `Makefile`: 볼 그래픽의 `--remove-xflip --keep-whitespace` 전처리

## 포획

볼 투척 → 볼 열림·연기 → 몬스터 축소 흡수 → 닫힘 → 네 번의 바운스 → 최대 세 번 흔들림 → 잠금 또는 탈출 순서다. 사용자의 최신 요청에 따라 성공 여부는 수학 정답으로 결정한다. 볼을 고르면 항상 문제가 나오고 정답이면 반드시 잡으며 3회 흔들린다. 오답·넘기기는 볼 1개를 쓰고 흔들림 없이 탈출한다. 실패 문구는 원본 탈출 대사와 수학 풀이 실패 안내를 함께 사용한다. 탈출 연출이 끝난 뒤 상대의 반격을 보여준다.

원본 `anim_wait` 값과 35프레임 볼 흔들림을 사용한다. 웹 전투 화면의 좌표와 몬스터 크기에 맞춰 투척 궤적·흡수 좌표를 배치한다. 원본 애니메이션 VM을 실행하거나 모든 상태의 프레임 동등성을 보장하는 방식은 아니며, 원작 사운드는 포함하지 않는다.

닫힌 볼이 분리되어 보였던 원인은 원본 Makefile의 반전 타일 제거 처리를 누락한 것이다. PNG 원본의 타일 번호 대신 전처리한 타일 스트림의 OAM 인덱스를 사용하도록 수정했다. 생성 프레임이 하나로 연결되어 있고 중심이 불투명한지도 브라우저에서 검사한다.

## 등장과 교대

전투 첫 등장, 일반 교대, 기절 후 교대를 지원한다. 일반 교대는 이전 몬스터 축소 회수(32프레임) 후 새 몬스터의 연기(4프레임)와 단계적 확대 등장(32프레임)을 재생한다. 첫 등장과 기절 교대에서는 회수를 생략한다. 일반 교대의 적 반격은 등장 연출이 끝난 뒤 재생한다. 기절 후 무료 교대에는 추가 반격을 넣지 않는다. 기존 포켓몬과 마인크래프트 몬스터 모두 같은 경로를 사용한다.

## 저장과 입력

`capture` 및 `sendout` 표시 이벤트에 계산 전후 몬스터, 결과·흔들림 횟수 또는 교대 대상·회수 여부를 기록한다. 볼 소비·파티/보관함 추가·교대·반격 계산은 한 번만 처리하고 즉시 저장한다. 연출 중에는 중복 입력을 막고, 새로고침하면 저장한 표시 이벤트만 재생한다. 정상 완료 후 잡힌 몬스터는 화면에 다시 나타나지 않고 볼 안에 남는다. 모션 줄이기는 짧은 페이드와 정적인 볼 표시를 사용하며, 이펙트 로딩 실패도 전투를 막지 않는다.

자산 재생성은 `tools/rebuild-assets.cjs`에서 공격 자산 생성기와 `build_capture_assets.py`를 실행한다. 회귀 검증은 루트 `npm run test:tralalerio`, 로컬 서버 실행 후 `npm run test:tralalerio-browser`다.

## 담 넘기

HOP 타일의 한 방향 이동 규칙은 엔진에 유지한다. 한 번에 2~3칸 이동하는 담 넘기를 320ms의 연속 이동과 포물선 높이로 표시하고, 공중 그림자를 그린다. 공중에서는 다음 이동 입력을 무시해 착지 전에 논리 좌표가 다시 이동하지 않도록 한다. 착지 위치와 충돌 규칙, 저장 좌표는 기존 엔진의 결과를 따른다.

이전 구현 기록(최신 수학 포획 정책으로 대체됨): 원본 `engine/items/item_effects.asm`의 `PokeBallEffect`처럼 3×최대 HP가 255를 넘으면 분자·분모를 먼저 2비트 우측 이동하고 하위 바이트로 나눗셈한다. 결과 최솟값 1, 수면·얼음 +10, 나머지 상태 보너스 없음(원본 버그), 0~255 난수 ≤ 최종 수치로 성공한다. 일반 몬스터볼만 판매하며 튜토리얼·마스터볼의 무조건 성공 분기는 적용하지 않는다. Minecraft 24종에도 동일 계산을 적용한다. 풀 체력 구구는 86/256, 포획률 220인 Minecraft 몬스터는 최대 HP에 따라 약 74/256이다. 모든 종의 256개 난수를 전수 검사해 성공 횟수와 실패 후 반격을 확인한다.

현재 실행 코드에는 HP 기반 `catchThreshold`와 흔들림 확률 함수가 없다. 새 포획 이벤트는 `mathCapture: true`를 기록하고, 옛 threshold 이벤트는 저장된 결과를 재생할 때만 허용한다. 정답 보상은 “수학 문제를 풀어서 [이름]을/를 잡았다!”이다. 검증은 `math-capture.test.js`, `browser-math-capture.mjs`, 기존 `browser-capture.mjs`를 포함한다.
