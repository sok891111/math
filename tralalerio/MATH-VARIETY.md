# 골고루 출제하기와 뺄셈 연습 (2026-10-25)

## 현재 적용된 방식

`math-schedule.js`는 매번 독립 균등 추첨하던 선택을, 묶음별 비중을 누적으로 맞추고 묶음 안에서 가장 오래 출제되지 않은 유형을 고르는 방식으로 바꾼다. 오래 안 나온 유형/아직 한 번도 안 나온 유형이 우선이며 동률일 때만 난수로 고른다. 직전 해결/넘김 유형의 연속 반복도 피한다. 전체 숙련도 기반 적응형 설계와는 별개로 실제 구현된 출제 다양성 기능이다.

일반전의 후보35종 중 뺄셈5종의 기존 비중은5/35=약14.29%였다. 요청의 “5% 정도 올리기”는 **5%포인트 추가**로 적용해 약19.29%로 바꾼다. 나머지30종은 합계 약80.71%다. 장기적으로 뺄셈 각 유형은약3.86%, 다른 각 유형은약2.69%다. 한 문제마다 같은 확률로 독립 추첨하는 것이 아니라, 출제 누적으로 목표 비중을 맞춘다. 보통5~6문제마다 뺄셈 한 번이 배치된다.

구현은 다음과 같다.

1. 출제할 수 있는 유형 중 뺄셈 수/전체 수 +0.05로 목표 비중을 계산한다.
2. 문제를 새로 만들 때마다 credit에 목표 비중을 더한다.1 이상이 되면 뺄셈을 고르고1을 뺀다. 그 외에는 다른 문제를 고른다.
3. 선택한 묶음에서 lastSeen이 가장 오래된 유형을 고른다. 아직 나오지 않은 유형은 가장 먼저 고른다.
4. 새 문제 한 번에 draws와 해당 유형의 lastSeen을 한 번만 기록한다. 정답/오답 여부와 관계없이 실제 노출이 기준이다.

이 방식은 뺄셈만 연달아 몰아서 채우지 않으면서, 다른 유형도 오래 방치하지 않게 한다. 같은 후보가 유지되는10000회 검증에서 뺄셈 비중이 목표값과1문제 이내로 일치하고, 일반전35종이 첫40문제 안에 모두 등장했다. 묶음 안의 유형별 총 출제 횟수 차이도 최대1이었다. 보스 후보19종은19문제마다 각각 한 번씩 등장한다.

## 저장과 상황 분리

- `state.mathSchedule={version:1,contexts:{ordinary,boss}}`에 출제 수·뺄셈 수·배분 잔여량·유형별 마지막 출제 순서를 저장한다.
- 공격 문제와 포획 문제는 같은 일반/보스 기록을 공유한다. 한쪽만 플레이해도 다양성이 유지된다.
- 일반전과 관장/전설은 후보가 달라 기록을 분리한다. 관장/전설은 기존 레벨5만 출제하며, 쉬운 뺄셈1~2는 후보에 추가하지 않는다.
- 기존 저장에는 기록이 없어도 정상 시작하며 새로부터 기록한다. 잘못된 기록은 출제에 필요한 부분만 초기화한다. 기존 동료/PC/배지/돈/관리자 지급 기록은 변경하지 않는다.
- 진행 중 문제를 다시 열거나 새로고침해도 새 문제를 선택하지 않으므로 순서를 더 소비하지 않는다. 저장 문제의 버전 이관도 출제 횟수를 늘리지 않는다.
- 지금의 기록은 기존과 같은 개인별 브라우저 저장이다. 서버/기기 간 동기화를 추가한 것은 아니다.

## 뺄셈 단계

5유형 모두 `[1,2]`를 지원한다: subtract_single, subtract_story, story_spend_chain, story_less_chain, table_story.

- 일반전 뺄셈의 목표 구성은 레벨1 약60%, 레벨2 약40%다. 문제 시드의 균등 구간으로 정하며 새로고침해도 같은 문제의 레벨이 변하지 않는다.
- 레벨1의 한 자리 뺄셈은 처음 수5 이하, 레벨2는9 이하이며 음수는 없다.0도 올바른 답으로 나온다.
- 두 번 빼기/적은 수의 관계/표와 이야기 유형도 레벨1에서는 숫자를 작게 사용한다. 읽기와 이야기의 구조는 해당 유형의 특성을 유지한다.
- 저장된 레벨1/2는 유지한다. 예전의 지원하지 않는 높은 뺄셈 문제는 비용 없이 지원 단계로 교체한다.
- 기존 덧셈의 중간/최종 합99 이하 제한은 그대로다.

## 개발실

개발실의 수동 유형/시드 선택은 그대로 정확한 문제를 재현한다. `무작위 문제` 버튼은 전체38종을 같은 공정 순환 방식으로 고른다. 후보 수가 다르므로 개발실의 뺄셈 목표 비중은5/38+0.05=약18.16%다. 이 기록은 개발실의 열린 세션 안에서만 유지하며 실제 모험 저장을 읽거나 쓰지 않는다. 개발실을 새로고침하면 개발실용 순환만 새로 시작한다.

`?type=subtract_single&grade=1&seed=12345`로 레벨1을 직접 재현한다. 초기 HTML 선택지에1이 없어서 URL의1이 사라지고2로 열리던 동작도 수정했다. 레벨 선택은 해당 유형의 지원 단계로 생성한 뒤 URL의 요청값을 적용한다.

- 일반과 보스의 분리, 저장 복원 후 동일한 다음 선택, 진행 중 문제/무료 이관의 출제 횟수 보존.

- 관장/전설5 정책, 저장 복원 후 정답 제출, 덧셈 범위 보존.

관련16개 테스트 통과. 콘텐츠별 정답 테스트는 `math-selection-fixture.mjs`에서 의도한 유형의 출제 차례를 만들어 검사하며, 실제 순환의 분포는 별도 `math-schedule.test.js`에서 검사한다. 옛 균등 추첨 난수 인덱스를 새 로직의 정답으로 가정하지 않는다.

`node tralalerio/tests/browser-math-schedule.mjs`: Chrome/WebKit의390px 터치 화면에서 레벨1 개발실 정답 제출, 무작위50회로 전체38종 출제와 뺄셈 비중, 실제 게임의 저장된 출제 순서 → 레벨1 포획 문제 → 새로고침해도 문제/순서 유지 → 정답 포획을 확인했다. 전체 게임 테스트는 실행하지 않는다.
