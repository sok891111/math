# 개인 URL 게임 상태 중앙 저장

개인 URL과 기존 개인 코드를 그대로 사용한다. 추가 로그인·비밀번호·기기 승인을 도입하지 않는다. 같은 URL을 공유하면 같은 게임 기록을 사용한다. URL 전달 자체를 기술적으로 차단하는 기능은 아니다.

## 저장과 최초 이관

- 대상: 블록섬, Runner(진행·캠페인·최고점·문제 맵 순서), 창의력 수학(기존 다리·현재 몬스터 원정대), 한자, 뜨랠레리오, 마법영어 Stage 1/2, 마법영어 블록 세계.
- 기기 음량·화면 설정, guest 기록, 개발용 violet-test 저장은 동기화하지 않는다. 기존 개인 저장 키와 직렬화 형식을 유지한다.
- 개인 로비·배지 화면 또는 게임에 처음 접속하면 그 브라우저에 이미 있는 개인별 게임 기록을 그대로 서버로 전송한다. 처음 게임으로 초기화하거나 임의 병합하지 않는다.
- 브라우저별 최초 이관 원본은 별도 불변 백업으로 저장한다. 각 게임의 모든 후속 업로드도 이력으로 남는다.
- 다른 브라우저에도 기존 기록이 있다면 그 브라우저의 최초 이관도 수행한다. 나중에 서버가 접수한 기록이 해당 게임의 현재 기록이 된다. 두 기존 기록 모두 이력에 남는다.
- 기록이 없는 새 브라우저에서는 빈 게임을 서버에 덮어쓰지 않고 기존 서버 기록을 먼저 가져온 뒤 게임을 시작한다.
- 서버는 다른 브라우저의 localStorage를 직접 읽을 수 없다. 배포된 서비스에 각 브라우저가 다시 접속해야 이관이 실행된다. localhost와 운영 도메인의 저장소는 별개다.

## 주기 저장과 오프라인

기존 게임은 진행을 localStorage에 계속 저장한다. 공통 모듈이 개인 페이지 진입 시 및 10분 주기로 변경된 게임 기록을 서버에 전송한다. 브라우저가 백그라운드 탭을 제한하면 실제 주기 실행은 늦어질 수 있다.

오프라인에서는 기존 로컬 진행을 유지한다. `online` 이벤트가 발생하면 대기 요청과 최신 로컬 기록을 전송한다. 서버 오류도 다음 주기 또는 다음 개인 페이지 진입 시 재시도한다. 업로드 도중 다시 연결되는 경우에도 후속 재시도를 예약한다. 페이지를 닫아도 원래 게임 기록과 미전송 요청이 브라우저에 남는다.

서버에 성공적으로 저장되기 전에는 '서버 저장 완료'를 표시하지 않는다. 로컬 기록도 없고 서버 연결도 실패하면 게임 시작을 막아 새 초기 기록이 만들어지는 것을 방지한다.

변경 없는 게임은 서버의 최신 기록을 가져온다. 실행 중인 게임에 다른 브라우저의 변경을 반영할 때는 기록을 적용한 뒤 페이지를 새로고침한다. 요청 중 발생한 로컬 변경은 덮어쓰지 않고 다음 저장 대상에 남긴다. 여러 기기가 같은 게임을 각자 진행하면 마지막으로 서버가 접수한 스냅샷이 현재 기록이 된다. 오프라인 기록도 재연결 후 마지막 접수 기록이 될 수 있다. 실시간 공동 플레이·자동 병합·동시 접속 제한은 제공하지 않는다.

## 서버 운영

기존 Supabase `kv_store(key, value)`를 사용한다. 신규 테이블이나 DB 마이그레이션은 필요 없다.

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY` 또는 기존 `SUPABASE_ANON_KEY`: 서버에서 `kv_store` 읽기·삽입 권한 필요. 브라우저에 전달하지 않는다.

키 접두사는 `block-central:`이며 마법영어 보상 원장과 분리된다.

- `<userId>:operation:<operationId>`: 요청 원본, 접수 시각, 재시도 중복 확인.
- `<userId>:migration:<browserId>`: 해당 브라우저 최초 이관 백업.
- `<userId>:game:<game>:<savedAt>:<operationId>`: 게임별 불변 상태 이력. 키 내 접수 시각 순서로 최신 스냅샷을 조회한다.

이력 삭제는 자동으로 하지 않는다. 운영 데이터량 증가를 관찰하고 장기 보관 정책을 별도로 정해야 한다. 요청 한도는 4MB다. 한도를 넘거나 저장 공간·네트워크 오류가 발생해도 기존 브라우저 기록을 초기화하지 않는다. 백업 복원은 관리자가 원본 이력을 확인하고 수행해야 하며 별도 복원 UI는 포함하지 않는다.

Vercel에서는 Supabase 미설정·오류 시 로컬 파일이나 메모리에 저장 성공을 가장하지 않는다. 로컬 Next 실행에서는 `.central-state-data/`에 파일로 저장한다. 해당 디렉터리는 Git에서 제외한다.

## 소스와 검증

- 저장 키: `lib/central-state/keys.cjs`
- 서버: `lib/central-state/store.cjs`, `pages/api/user/[userId]/state.js`
- 브라우저: `scripts/central-state-client.js`
- HTML 시작 순서: `lib/central-state/html.cjs`
- React 로비·배지 시작 순서: `pages/_app.js`

`public/central-state*.js`는 `scripts/sync-public.cjs`가 복사하는 생성 파일이다.

```sh
npm run test:central-state
npm run build
npm run test:central-state-browser
```

브라우저 검증은 임시 사용자·임시 로컬 저장소와 4194 포트의 실제 Next 서버를 사용한다. 운영 사용자·Supabase 기록은 수정하지 않는다. 기본 Chrome 경로는 macOS Google Chrome이며 `CHROMIUM_PATH`로 변경할 수 있다.
