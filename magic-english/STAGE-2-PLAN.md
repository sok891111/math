## 3. 원작에서 유지할 사건과 감정

1. A 조각과 활빈을 되찾은 일행이 공항 밖으로 나온다.
2. 사라진 보따리에는 주먹밥뿐 아니라 **길동이 고향과 자신을 기억하게 하는 활빈당 표식**이 있다.
3. 미스터 미스스펠과 노노·웅얼이·따라쟁이가 표지판과 안내를 헷갈리게 만든다.
4. 잘못 탄 버스에서 길동은 다시 도움을 요청하는 용기를 낸다.
5. 급하게 달리던 길동이 멈춰 글자 순서를 확인하고 소리 내어 읽는다.
6. B 조각을 얻고 큰 파란 버스에서 보따리와 표식을 되찾는다.
7. 진짜 버스에 올라 다음 화 C의 학교를 예고한다.

잘못된 버스 탑승은 실제 정답 선택을 실패 처리하는 방식으로 만들지 않는다. **버스 선택 평가를 시작하기 전 짧은 원작 사건 연출**로 보여주고, 이후에는 플레이어가 바르게 판단한 결과를 인정한다. 보따리를 되찾는 장면은 블록 지급 알림보다 먼저 충분히 보여준다.

## 4. 플레이 흐름

| 단계 | 실제 플레이 | 영어와 즉시 반응 | 진행 결과 |
|---|---|---|---|
| 1. 공항 밖 | 활빈과 주변을 살피다 보따리가 없음을 발견 | `Bag`와 보따리 그림 연결 | 보따리 찾기 목표 표시 |
| 2. 정류장 탐색 | 큰 버스·짐칸·표지판을 직접 조사 | `Bus`, `Bag`, `Big`을 듣고 대상 찾기 | 오늘의 세 단어 기록 |
| 3. 잘못 탄 버스 | 삼총사의 방해와 탑승을 짧게 연출 | 길동의 당황, 활빈의 응원 | 기사에게 도움 요청 목표 |
| 4. 기사에게 묻기 | 직접 말하고 기사의 답을 듣기 | `Excuse me. Can I ask?` → `Where is the bus?` | 다음 정류장 하차·새 길 개방 |
| 5. 표지판 복구 | 정류장 길을 걸으며 BUS·BAG·BIG의 순서 바로잡기 | 완성한 단어를 소리 내어 읽으면 간판 복구 | 미스스펠의 방해 해소 |
| 6. 보따리 회수 | 큰 파란 버스를 찾아 짐칸 조사 | `Big bus!`, `My bag!` | B 조각·보따리·표식 회수 |
| 7. 다음 여행 | 올바른 버스 탑승과 창밖 학교 예고 | 친구들과 짧게 복습 | Stage 2 완료·Stage 3 예고 |
| 8. 선택적 건축 | 같은 개인 코드로 내 블록 세계 열기 | 보상 블록 수령 확인 | 내 정류장 자유 건축 |

대화만 차례대로 누르는 흐름을 피한다. 표지판을 찾아 걷기, 크기가 다른 버스 관찰, 보따리 흔적 조사, 간판 복구와 마지막 짐칸 발견을 플레이로 만든다. 시간 제한 추격이나 정밀 점프는 넣지 않는다.

- [ ] 공항 앞 정류장 맵: 출구·버스·짐칸·안내판·삼총사 배치.
- [ ] 버스 실내 맵: 기사와 대화하고 하차하는 짧은 공간.
- [ ] 다음 정류장 맵: 복구할 간판과 큰 파란 버스, 보따리 회수 지점.
- [ ] 기존 골드 방식의 이동·충돌·출입·대화 UI를 재사용하고 마법영어용 장소와 자산으로 구성한다.
- [ ] 모험 조작은 화면 방향키와 A 확인/조사, B 대화 닫기/뒤로 가기를 기본으로 한다.
- [ ] 문제 선택은 큰 버튼 탭으로 처리한다. 정밀 드래그·작은 글자 타이핑은 필수로 만들지 않는다.
- [ ] 목표는 한 번에 하나만 표시한다. 예: ‘기사님에게 버스가 어디 있는지 물어보자’.
- [ ] 상호작용 대상에 가까워지면 조사할 수 있음을 그림이나 테두리로 알린다.
- [ ] 이동·탑승·하차·장면 전환 중 입력 중복과 메뉴 진입을 잠근다.
- [ ] 버스 이동은 짧은 창밖 연출로 처리한다. 운전·도로 교통 시뮬레이션은 만들지 않는다.

## 6. 영어 활동과 판정

### 핵심 표현

| 역할 | 표현 |
|---|---|
| Stage 1 복습 | `Excuse me. Can I ask?` |
| 새 의사소통 | `Where is the bus?` |
| 소유·발견 표현 | `My bag!` |
| 관찰 표현 | `Big bus!` / `It is big.` |
| 읽기 | `Bus`, `Bag`, `Big` |

기사에게 묻는 `Where is the bus?`는 **버스의 위치를 찾는 질문**으로 연출한다. 목적지를 묻는 문장으로 번역하지 않는다. B의 글자 이름 ‘비’와 단어 첫소리 /b/도 구분해 들려준다.

- [ ] ‘단어 듣기 → 실제 대상 찾기 → 말해 보기’를 같은 사건 안에서 연결한다.
- [ ] 기사 대화는 짧은 구절로 나누어 연습하거나 이어 말할 수 있게 한다.
- [ ] 마이크 입력과 인식 결과로 판정한다. 버튼 누르기나 소리 크기만으로 말하기 성공 처리하지 않는다.
- [ ] 다시 듣기·전체 문장·첫 구절 도움을 제공하고, 도움받은 완료도 이야기와 보상은 동일하게 인정한다.
- [ ] `BUS`·`BAG`·`BIG`은 섞인 글자 세 개를 탭해 순서를 정하는 작은 활동으로 만든다.
- [ ] 잘못 놓은 글자는 다시 고를 수 있다. 정답을 못 찾으면 그림과 단어 소리로 풀이 방향을 안내한다.
- [ ] 문자를 복구한 다음 실제로 읽는 단계를 연결한다. 모든 간판마다 긴 문장을 반복시키지는 않는다.
- [ ] `SUB`·`GAB` 등의 표시는 버스/가방을 뜻하는 목표 단어와 순서가 다르다는 수준으로 설명한다.
- [ ] 거절·무음·인식 실패 시 다시 시도하거나 함께 말하기 경로를 제공한다. 보유 블록이나 스토리 진행을 차감하지 않는다.
- [ ] 직접 말한 완료와 지원 경로 완료를 기록하되, 발음 점수 경쟁·시간 제한·강제 큰 목소리는 넣지 않는다.

## 7. 퀘스트와 건축 보상 제안

수치는 Stage 2 시제품 제안값이다. 구현 시 아래 내용을 고정한 뒤 지급하고, 이미 발행한 ID의 수량·설명을 바꾸지 않는다.

| 퀘스트 | 완료 조건 | 추가 블록 | 고정 rewardId |
|---|---|---|---|
| 표지판을 알아봤어요 | Bus·Bag·Big 발견 활동 완료 | 돌 3개·참나무 판자 3개 | `stage2:quest:discover-b:v1` |
| 기사님에게 물었어요 | 질문과 기사의 응답 완료 | 유리 2개 | `stage2:quest:ask-driver:v1` |
| 보따리를 되찾았어요 | 간판 복구·보따리 회수·B 조각 완료 | 벽돌 4개·하얀 블록 4개·파란 블록 4개 | `stage2:quest:recover-bag:v1` |

총 추가 보상은 **20개**다. 기본 시작 물량인 잔디·흙·돌·참나무 판자 각 5개는 Stage 2 진입 시 다시 지급하지 않는다. 이미 소비한 수량·Stage 1 보상·기존 건축물을 그대로 이어간다.

- [ ] 각 퀘스트 완료 직후 받은 블록 그림과 수량을 짧게 보여준다.
- [ ] 같은 대상을 다시 조사하거나 대화를 반복해도 같은 보상을 재발행하지 않는다.
- [ ] 동물 공격·반복 단어 연습은 별도 블록 파밍 경로로 만들지 않는다.
- [ ] B 조각은 모험의 진행 기록으로 저장한다. 현재 블록 지급 API에 B 조각을 블록 ID처럼 보내지 않는다.
- [ ] 완성형 버스·표지판·설계도·장식 아이템은 현재 API 지원 항목이 아니므로 이번 필수 보상에서 제외한다.

```json
  "reason": "Stage 2 보따리 회수와 B 조각 완료",
  "blocks": [
    { "blockId": 10, "quantity": 4 },
    { "blockId": 13, "quantity": 4 },
    { "blockId": 19, "quantity": 4 }
  ]
}
```

- [ ] 모험 서버에 퀘스트 완료와 지급 대기 항목을 함께 기록한다.
- [ ] 서버 환경의 `BLOCK_REWARD_API_KEY`로 `POST /api/block-world/rewards`를 호출한다. 키를 브라우저에 넣지 않는다.
- [ ] 다른 두 퀘스트도 표의 고정 ID·수량·고정 설명으로 발행한다.
- [ ] `200/201`이면 등록 완료로 기록한다. `created: false`도 정상 성공이다.
- [ ] 타임아웃·서버 오류는 같은 ID와 본문으로 재시도하고 `409`는 내용 충돌로 다룬다.
- [ ] API가 끊겨도 보따리 회수와 이야기 완료는 유지하고, 보상만 ‘전달 대기’로 표시한다.
- [ ] 서버 등록 성공을 브라우저 실제 수령 완료로 표시하지 않는다. 블록 숲의 수량·영수증 저장이 완료되어야 실제 수령이다.
- [ ] `userId`와 블록 숲 URL의 `user`를 일치시킨다. 체험 경로는 API의 `demo` 규칙을 따른다.

지급 서버·자동 수령 클라이언트는 기존 구현을 재사용한다. 별도의 무인증 지급 함수나 퀘스트 화면에서 `localStorage` 잔고를 직접 더하는 코드를 만들지 않는다.

## 9. 내 세계로 이동하기

- [ ] 안전한 정류장 상태와 Stage 2 완료 화면에 ‘내 세계 만들기’를 제공한다.
- [ ] 같은 사용자 코드의 `/block-world/?user=<개인코드>&controls=easy`로 이동한다.
- [ ] 모험의 복귀 위치·현재 단계·완료된 활동을 저장한다. 버스 이동 연출 도중에는 전환하지 않는다.
- [ ] 블록 세계에서 ‘모험으로 돌아가기’ 경로를 연결한다. 현재 독립 건축 게임에 모험 복귀 기능이 이미 있다고 가정하지 않는다.
- [ ] 돌·판자·유리·색 블록으로 작은 정류장을 만드는 그림 예시를 선택적으로 보여준다.
- [ ] 건축 완성 검사나 정답 배치는 필수로 넣지 않는다. 보상을 어디에 쓸지는 아이가 결정한다.
- [ ] 보유 블록이 0개여도 Stage 2 모험을 시작하거나 끝낼 수 있게 한다.
- [ ] 건축을 건너뛰어도 다음 이야기로 진행할 수 있게 한다.

건축 게임의 그래픽·자유 드래그 시점·부드러운 앞뒤/좌우 이동·점프·막대기·돼지/닭은 유지한다. 비행이나 한 칸 이동/90도 회전을 다시 도입하지 않는다.

## 10. 저장·복원과 중복 실행 방지

Stage 2 상태는 마법영어 모험 저장에 버전과 함께 추가한다. 기존 포켓몬 저장이나 블록 세계를 초기화하지 않는다.

```text
stage2.version
stage2.phase
stage2.discoveredWords
stage2.driverConversation   # 미시작 / 연습 / 응답완료, 직접말하기·지원 경로 구분
stage2.signs                # 간판별 현재 선택과 복구 완료
stage2.bagRecovered
stage2.fragmentB
stage2.nextBusBoarded
stage2.rewardDelivery       # 퀘스트별 미완료 / 전달대기 / 서버등록완료
adventureReturnPoint
```

- [ ] 잘못 탄 버스 연출·기사 응답·하차·표식 회수·B 조각·다음 버스 탑승의 중간 단계도 복원한다.
- [ ] 완료 플래그와 연출 진행 단계를 구분하여 재접속 시 보상이나 탑승을 반복하지 않는다.
- [ ] 녹음 중 재접속하면 자동 녹음을 시작하지 않고 다시 말하기 화면으로 돌아간다.
- [ ] 퀘스트 완료 검증과 보상 등록 대기는 서버의 신뢰 가능한 기록을 기준으로 한다.
- [ ] ‘내 세계’ 왕복 후에도 이야기 단계와 지급 대기 상태를 보존한다.
- [ ] 읽을 수 없는 저장을 새 시작으로 자동 덮어쓰지 않는다.

## 11. 구현 순서

1. Stage 1과 공유할 모험 저장·말하기·사용자 식별 계약 확정.
2. 정류장·버스 실내·다음 정류장과 기본 이동/조사 연결.
3. 보따리 발견부터 기사 대화·간판 복구·회수까지 한 번에 플레이 가능한 흐름 완성.
4. 실제 말하기와 실패/지원 경로 연결.
5. 세 퀘스트의 서버 완료 검증·지급 대기·API 재시도 연결.
6. 블록 숲 이동·수령·자유 건축·모험 복귀 연결.
7. iPad 가로/세로 터치 및 저장 복원·중복 지급 집중 검증.

## 12. 완료 기준

- [ ] 아이가 ‘왜 보따리를 찾아야 하는지’와 다음 행동을 이해한다.
- [ ] NPC 대화 외에 직접 걷기·관찰·표지판 조작·발견의 플레이가 있다.
- [ ] 실제로 질문하면 기사가 응답하고 다음 길이 열린다.
- [ ] 간판을 바로잡고 읽으면 현장의 글자와 길이 복구된다.
- [ ] 말하기 지원 경로로도 보따리·표식·B 조각을 얻을 수 있다.
- [ ] 원작의 보따리 회수와 고향 표식의 감정, C 학교 예고가 남는다.
- [ ] 세 퀘스트 보상은 각각 한 번만 등록되며 합계 20개가 추가된다.
- [ ] 재대화·새로고침·API 재시도·건축 왕복으로 수량이 부풀지 않는다.
- [ ] 지급 API가 끊겼다가 복구되어도 이야기 진행을 잃거나 보상을 놓치지 않는다.
- [ ] Stage 1 기록·기존 건축·수량·영수증·사용자별 저장이 유지된다.
- [ ] 아이패드에서 마우스·물리 키보드 없이 모험과 보상 건축을 이어갈 수 있다.

검증 시 기존 `npm run test:blocks`, `test:blocks:easy`, `test:blocks:animals`, `test:blocks:rewards`를 변경 범위에 맞게 사용하고, Stage 2에는 대화/연출 복원·말하기·API 재시도·모험 왕복을 확인하는 별도 회귀를 추가한다. 실제 iPad의 마이크 권한과 음성 입력도 별도로 확인한다. 계획 문서 작성만으로 게임 테스트를 실행하지 않는다.
