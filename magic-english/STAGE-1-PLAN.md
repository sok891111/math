**공항에서 활빈을 찾고, 실제로 영어를 말해 A 조각을 얻은 뒤, 보상으로 별도의 블록 세계에서 첫 건축을 하는 경험**을 완성한다.

- 모험은 포켓몬 골드 방식의 탑다운 이동·NPC 대화·이벤트 연출을 활용한다.
- 스토리는 `/Users/gimseongjin/english_book/book_1/마법영어_1화_스토리.md`를 기준으로 한다.
- 로블록스의 `EnglishStoryData.luau`는 단계 구성의 참고 자료로 활용한다. 버튼 연타를 실제 말하기 판정으로 취급하지 않는다.
- 플레이 시간 목표는 모험 10~15분, 이후 자유 건축이다. 실제 플레이로 조정한다.
- 포획·몬스터 육성·수학 문제는 새 마법영어 모드의 진행에 사용하지 않는다.
- 기존 포켓몬 모험과 개인 저장·관리자 지급 기록은 유지하고, 새 모드와 저장을 분리한다.

## 3. 모험 구현 체크리스트

- [ ] 새 마법영어 모드 진입점과 기존 모험을 구분한다.
- [ ] 공항 맵 하나에 수하물 벨트·안내 데스크·출구·조사 대상을 배치한다.
- [ ] 길동·활빈·에이미·링고·직원·미스스펠의 최소 그래픽을 준비한다.
- [ ] 기존 책의 이미지와 캐릭터 자료를 확인하고 사용할 자산을 정리한다.
- [ ] 키보드·터치 이동, 말 걸기, 조사, 대화 넘기기를 연결한다.
- [ ] 현재 목표를 한 줄로 표시한다. 예: ‘안내 직원에게 활빈을 찾을 방법 물어보기’.
- [ ] 세 단어는 실제 물건·표지·행동과 연결하고, 조사 순서는 자유롭게 한다.
- [ ] 각 단어에 그림·뜻·다시 듣기 기능을 제공한다. 글자 이름과 단어 속 소리를 구분한다.
- [ ] 발견한 대상을 반복 조사해도 진행·보상을 중복 처리하지 않는다.
- [ ] 주요 연출 중 이동·중복 상호작용을 막고 완료 후 입력을 복구한다.
- [ ] NPC별 대사와 등장 조건을 스토리 데이터로 분리한다.

## 4. 실제 말하기 구현 체크리스트

- [ ] ‘들어보기 → 마이크로 말하기 → 상대의 반응’ 흐름을 구현한다.
- [ ] “Excuse me.”와 “Can I ask?”를 나누어 연습하거나 이어 말할 수 있게 한다.
- [ ] 마이크 권한 요청, 녹음 중 표시, 종료, 재시도, 오류 안내를 구현한다.
- [ ] 대상 기기에서 사용할 음성 인식 방식을 먼저 검증한다. 공급자·비용은 구현 착수 시 결정한다.
- [ ] 인식 결과와 허용 표현으로 판단하며, 소리가 났다는 이유만으로 정답 처리하지 않는다.
- [ ] 대소문자·문장부호 차이와 명시한 허용 표현을 처리한다. Stage 1에서는 무제한 자유 대화 판정을 만들지 않는다.
- [ ] 문장 전체 지원·첫 구절 지원·다시 듣기를 제공한다.
- [ ] 인식 불확실·권한 거절·지원하지 않는 기기에서는 함께 말하기/직접 확인 경로로 진행할 수 있게 한다.
- [ ] 스스로 말한 완료와 도움받은 완료를 구분해 기록하되, 이야기·건축 보상은 동일하게 지급한다.
- [ ] 실패·재시도로 보상이나 자원을 차감하지 않는다.
- [ ] 원본 음성은 기본적으로 저장하지 않는다. 외부 전송을 사용하는 경우 녹음 전에 설명한다.

## 5. 건축 보상과 별도 게임 연결

### Stage 1 보상 제안

| 보상 | 용도 | 지급 규칙 |
|---|---|---|
| A 알파벳 조각 | 이야기 진행·수집판 표시 | 최초 완료 1회 |
| 건축 블록 보상 | 참나무 판자 5개·벽돌 3개 추가 (제안) | 퀘스트별 고정 보상 ID로 최초 완료 1회 |
| 공항 블록 묶음 | 유리·흰 블록·파란 블록 각 3개 (제안) | 최초 완료 1회 |
| 종이비행기 장식 | 여행의 추억을 건축 세계에 배치 | 최초 완료 1회 |

초기 수량은 잔디·흙·돌·참나무 판자 각 5개이며 설치 시 1개를 소비한다. 직접 놓은 블록을 지우거나 되돌리면 수량도 복구한다. 위 표의 추가 보상은 Stage 1 설계 제안이고, 실제 퀘스트 완료 시 블록 지급 API를 호출해 연결한다. 코인 상점과 무제한 배치는 현재 구현 범위에서 제외한다.

- [ ] 모험과 별도 화면/경로의 건축 게임을 연결한다.
- [ ] 기존 건축 프로젝트 재사용 가능성을 확인한 후 연결 방식을 정한다. 아직 특정 외부 프로젝트와의 연동을 전제하지 않는다.
- [ ] 개인 건축 공간 하나와 블록 선택·쌓기·철거·시점 조작을 구현한다.
- [ ] 입체적으로 쌓을 수 있는 작은 공간으로 시작한다. 예: 가로 16 × 세로 16 × 높이 8칸.
- [ ] Stage 1 완료 서버 처리에서 고정 rewardId로 블록 지급 API를 호출한다.
- [ ] 완료 화면에서 받은 보상을 보여 주고 ‘내 세계로’ 버튼을 제공한다.
- [ ] 건축 화면의 ‘모험 이어하기’로 공항의 안전한 위치에 돌아온다.
- [ ] 건축 진입은 선택 사항으로 두고, 나중에도 메뉴에서 들어갈 수 있게 한다.
- [ ] 이동·회전·배치·철거가 터치 기기에서도 가능하게 한다.

## 6. 저장과 중복 보상 방지

- [ ] 마법영어 저장 키를 기존 `tralalerio-save-v1[:개인코드]`와 분리한다.
- [ ] 개인코드별 모험·건축 기록을 분리하고, 체험 사용자도 별도 저장한다.
- [ ] 저장에 버전·현재 단계·발견 기록·말하기 완료 방식·A 조각·보상 지급 ID를 포함한다.
- [ ] 건축 데이터에 블록 좌표·종류·장식·수량·설치 출처·보상 영수증을 저장한다.
- [ ] 보상 지급 ID는 고정한다. 예: `stage-1-first-clear`.
- [ ] 완료·보상 영수증·블록 수량 반영을 한 저장 작업으로 확정한다. 건축 화면을 열었다는 이유로 다시 지급하지 않는다.
- [ ] 재시도·대화 반복·새로고침·화면 왕복으로 보상이 늘어나지 않게 한다.
- [ ] 연출 중 새로고침하면 저장 단계부터 안전하게 재개한다. 녹음은 자동 재시작하지 않는다.
- [ ] 기존 저장이 읽히지 않을 때 자동 초기화하지 않는다.

첫 시제품은 같은 기기·브라우저의 저장을 기준으로 한다. 모험과 건축은 동일 출처의 별도 화면으로 시작해 보상과 저장을 공유한다. 다른 출처 서비스로 연결하거나 기기 간 동기화가 필요해지면 서버 저장·지급 API를 별도 설계한다.

## 7. 권장 작업 순서

1. 공항 맵·NPC·단계 데이터·새 저장 구조를 만든다.
2. 조사와 대화만으로 활빈 재회까지 이어지는 흐름을 연결한다.
3. 실제 녹음·인식·도움받기 경로를 연결한다.
4. A 조각·보상 1회 지급과 복원을 완성한다.
5. 별도 블록 세계의 배치·철거·수량·보상 수령·저장을 연결한다.
6. 키보드·터치·음성 오류·새로고침을 포함해 전체 흐름을 검증한다.

개발용 건너뛰기는 일반 플레이와 분리하며, 말하기 기능 완료로 간주하지 않는다.

## 8. 완료 기준

- [ ] 처음 시작한 아이가 목표를 보고 공항을 탐험해 활빈을 찾을 수 있다.
- [ ] 실제 마이크 입력으로 직원에게 말하고, 직원의 반응을 볼 수 있다.
- [ ] 음성 인식이 실패해도 지원 경로로 끝까지 진행할 수 있다.
- [ ] A 조각과 건축 보상이 정확히 한 번 지급된다.
- [ ] 받은 블록으로 실제 입체 건축을 하고, 철거·다시 배치할 수 있다.
- [ ] 새로고침과 모험/건축 왕복 후에도 진행·코인·건축물이 유지된다.
- [ ] 다른 개인코드 및 기존 포켓몬 저장에 영향을 주지 않는다.
- [ ] 단계 전환·말하기 판정·중복 지급 방지·건축 저장의 집중 검증과 브라우저 전체 흐름 검증을 수행한다.
- [ ] 구현 시 실제 실행 환경과 스크립트를 확인하고, 기존 코드 변경 범위에 맞는 회귀 검증을 실행한다. 현재 README의 상위 저장소 실행 명령은 이 체크아웃과 다를 수 있다.
